# 問題追加スキル

## 概要

`questions.js` の `POOL` 配列に問題を追加する。
難易度は**原則「難」**。10〜15分じっくり考える価値のある問題を作ること。

---

## 引数

| カテゴリキー | 分野名 | 解答形式 |
|-------------|--------|---------|
| `fermi` | フェルミ推定 | numeric |
| `logic` | 論理パズル（嘘つき・対応・順序） | choice |
| `deduction` | 推理問題 | free |
| `lateral` | 水平思考 | free |
| `syllogism` | 三段論法・条件整理 | choice |
| `probability` | 確率・期待値 | choice または numeric |
| `sequence` | 規則性・数列 | numeric または free |
| `critical` | クリティカル思考 | free |

引数なしの場合は、現在の POOL の分野別件数を確認して不足している分野を補う。

---

## データ構造（全フィールド）

```javascript
{
  id:      "f5",          // カテゴリ頭文字 + 連番（既存IDと重複しないこと）
  cat:     "fermi",       // カテゴリキー
  lvl:     "難",          // "難" または "中"（原則"難"）
  type:    "numeric",     // "numeric" | "choice" | "free"
  title:   "問題タイトル（20字以内）",
  body:    "問題文（\\n で改行）",

  // ── numeric 専用 ──
  unit:    "万杯",        // 単位（回答入力欄に表示）
  answer:  1800,          // 代表値（数値・単位は unit 参照）
  low:     600,           // 正解の許容下限
  high:    4000,          // 正解の許容上限
  scale:   1,             // 表示スケール（万単位なら1、本単位なら10000など）

  // ── choice 専用 ──
  choices: ["選択肢A", "選択肢B", "選択肢C", "選択肢D"],
  correct: 0,             // 正解のインデックス（0〜3）

  // ── 全形式共通 ──
  model:   "模範解答（3文以上）",
  explain: "解説（考え方の手順＋日常応用）",

  // ── 任意 ──
  acceptNote: "採点補足（numeric で複数正解があるときなど）"
}
```

---

## 難易度基準

### 「難」の定義（全カテゴリ共通）
- 一般人が即答できない
- 試行錯誤・場合分け・逆算が必要
- 10〜15分を要する質と情報量

### カテゴリ別ルール

#### fermi
- 分解ステップが**3段以上**必要（人口→割合→頻度 など）
- 代表解・低・高の三値は実データと整合していること
- `explain` に「■考え方の型」「■日常応用」を明記

#### logic（嘘つき・対応・順序）
- 条件は**4つ以上**（少ないと自明になりやすい）
- 候補を絞り込むのに**3手以上**の推論ステップが必要
- 場合分けや背理法が必要な構造にする
- choice の正解インデックスは 0〜3 をランダムに使う

#### deduction
- 伏線（手がかり）を**2本以上**仕込む
- 問題文だけから一意に絞れる（曖昧にしない）
- `model` は「最も自然な説明」を示す

#### lateral
- 「当然の枠」（職業・種・目的・方向）を外す仕掛けを入れる
- 問題文に答えが透けてはいけない
- `explain` に「■型」（外した枠の名前）を書く

#### syllogism
- 「すべて」と「ある（存在）」の混同、逆・裏・対偶の誤りを問う
- choice 誤答は「それっぽいが論理的に誤り」のものにする
- ベン図で考えると解けるように設計する

#### probability
- 直感と正解が逆になる構造（条件付き確率・ベイズ・期待値の罠）
- 「実数に直して考える」パターンを優先
- numeric の場合 low===high で完全一致を求めても良い（exact answer）

#### sequence
- 差・比・階差・複数項の和など、複数の方向性で解ける構造を避ける
- 規則が一意に確定するように設計する
- `explain` に「■型」（どの操作で見える規則か）を書く

#### critical
- 生存者バイアス・基準率の無視・相関と因果・前提の未検討 などを問う
- `body` に「この主張のどこがおかしいか」「何を確認すべきか」を明記
- `explain` に「■型」（思考の欠陥の名前）「■日常応用」を書く

---

## 模範解答・解説の必須要件

### `model`（3文以上）
- 直接的な答えを1文で示す
- 答えの根拠・プロセスを続ける
- 「なぜそうなるか」の一言まとめで締める

### `explain`（考え方の手順）
- fermi: 「分解→仮定→計算→検証」の4ステップを踏む
- logic/syllogism: 「仮定→矛盾の検証→確定」の流れ
- deduction: 「手がかりの列挙→消去法→確定」
- lateral: 「暗黙の前提の列挙→外す→整合の確認」
- critical: 「問題の核心を一言→論理の欠陥の説明→修正するなら何が必要か」
- 末尾に必ず「■型：（汎用の思考パターン名）」と「■日常応用：（職場・生活での具体場面）」を付ける

## 品質チェックリスト（追加前に確認）

- [ ] `id` が既存 POOL のどのエントリとも重複していない
- [ ] `lvl:"難"` であること（例外として妥当な理由がある場合のみ "中"）
- [ ] 問題文（`body`）に答えが滲み出ていない
- [ ] `model` が 3 文以上
- [ ] `explain` に「■型」「■日常応用」が含まれている
- [ ] numeric の場合：`low`・`high`・`scale` が設定されている
- [ ] choice の場合：`choices` が 4 択、`correct` が 0〜3 の整数
- [ ] 既存の類似問題と主旨・構造が被っていない

---

## 実行手順

### Step 1：既存 POOL を確認する

`questions.js` を Read し、以下を確認する：
- 既存の ID 一覧（次の連番を決める）
- 分野別の問題数（不足分野を優先）

### Step 2：問題を設計する

- 上記ルールに従い問題データを設計する
- `explain` の「■型」「■日常応用」を先に決めると逆算しやすい
- numeric は「代表解→low/high の設定」まで計算する

### Step 3：品質チェックリストを通す

設計した問題が全項目をクリアしているか確認する。

### Step 4：`questions.js` に追記する

`questions.js` を Edit して、POOL 配列の末尾 `];` の直前に追加する。

```javascript
// 末尾の例
{id:"f5", cat:"fermi", ...},  // ← ここに追加
];
```

### Step 5：追加完了を報告する

追加した問題の `id`・`cat`・`title` と、追加後の POOL 総件数を報告する。
